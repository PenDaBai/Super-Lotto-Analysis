# 大乐透玄学研究所

一个基于本地数据的体彩大乐透查询、分析和娱乐选号网页。项目的核心目标不是预测结果，而是把历史开奖号码整理成可查询、可视化、可解释的数据体验，满足“明知道没有规律，但还是想看看”的好奇心。

> 本项目所有分析、趋势、评分和选号结果均仅供娱乐，不构成购彩建议。

## 项目亮点

- **完整历史数据**：主数据源使用结构化 JSON，便于校验、分析、同步和前端直接加载。
- **号码查询**：支持按期号、日期、号码检索历史开奖，也可以输入或手动选择号码，检查历史中奖情况。
- **中奖判断**：按大乐透规则判断一组号码在历史每期中的最高奖级，并支持筛选只看指定奖级。
- **丰富分析卡片**：支持全部、近 200 期、近 100 期、近 50 期、近 30 期、近 10 期和自定义区间。
- **可视化分析**：冷热号码、遗漏观察、结构分布、组合共现、号码矩阵、临号回声、日历呼应、数学纹理、形态节奏、趣味玄学等。
- **分析驱动选号**：选号器会读取当前区间的分析画像，生成单式或复式号码，并展示生成依据、结构摘要和趣味评分。
- **本地运行**：第一版不依赖后端数据库，数据、分析和选号逻辑都在本地完成。

## 数据说明

项目不再把 Markdown 作为运行时主数据源。

- `data/dlt-draws.json`：应用运行使用的唯一可信主数据源。
- `data/dlt-meta.json`：保存数据版本、总期数、最新期号、最新日期、来源和生成时间。
- `dlt_history_FULL.md`：保留为原始归档、导入来源和可导出的展示格式。

JSON 中号码使用数字数组保存，例如：

```json
{
  "issue": "26051",
  "date": "2026-05-11",
  "front": [1, 6, 14, 15, 17],
  "back": [2, 3],
  "source": "official",
  "importedAt": "2026-05-14T00:00:00.000Z"
}
```

展示时再格式化为 `01`、`02` 这种两位号码。

## 更新开奖数据

平时只需要执行一条命令：

```bash
npm run sync:dlt
```

这个命令会读取中国体彩网官方历史接口，并从本地最新期开始自动补齐缺失数据。

如果很久没更新，担心中间断档，可以加大拉取范围：

```bash
npm run sync:dlt -- --limit=200
```

`limit` 表示向官方拉最近多少期。断档越久，可以把数值调大。

更新后建议检查一次：

```bash
npm run data:validate
```

常用数据命令：

```bash
npm run data:import-md
npm run data:validate
npm run data:export-md
npm run sync:dlt
```

- `data:import-md`：从 `dlt_history_FULL.md` 重新生成 JSON，平时不需要。
- `data:validate`：校验期号、日期、号码范围、重复号码和重复期号。
- `data:export-md`：从 JSON 导出 Markdown，平时不需要。
- `sync:dlt`：从官方接口同步最新开奖数据，日常更新主要用它。

## 功能模块

### 首页仪表盘

- 最新开奖
- 总期数
- 最新日期
- 数据健康状态
- 查询、分析、选号、数据管理快捷入口

### 查询

- 按期号、日期、号码搜索
- 输入或手动选择号码
- 支持单式和复式思路的中奖检查
- 统计历史上中过几次一等奖、二等奖、三等奖等
- 可筛选只显示指定奖级，默认关注一、二、三等奖

### 分析

分析页支持全局区间切换，区间选择会跟随页面滚动，便于边看卡片边切换样本范围。

已有分析方向包括：

- 热门 / 冷门号码
- 当前遗漏、最大遗漏、平均遗漏
- 奇偶比、大小比、和值、跨度、连号、同尾号
- 前区三区分布、后区结构
- 组合共现、后区搭配频率
- 日历呼应
- 号码矩阵
- 临号回声
- 数学纹理
- 形态节奏
- 趣味玄学评分

### 选号

选号页是娱乐化的“分析驱动选号仪式”：

- 支持区间：近 30 期、近 50 期、近 100 期、近 200 期、全部
- 支持模式：单式、复式
- 支持策略：综合罗盘、均衡形态、冷热混元、遗漏回响、数学纹理、日历呼应、纯随机
- 支持约束：前区定胆、后区定胆、前区排除、后区排除、偏好形态
- 支持生成：1 注、5 注、10 注
- 结果展示：号码球、签文、结构标签、选号依据、五维趣味评分

复式模式会展示该复式包含多少注单式组合，仅作为娱乐计算，不涉及金额或购买建议。

### 数据管理

- 单期新增
- 批量导入 JSON / Markdown
- 导出 JSON / Markdown
- 数据校验报告
- 同步脚本说明

浏览器内新增的数据默认保存在本地状态或本地存储，不直接改项目文件。需要持久化时，应导出 JSON / Markdown 后再由脚本或人工替换项目数据。

## 开发规范

项目规范见：

```text
docs/PROJECT_SPEC.md
```

核心约定：

- 单个业务文件尽量控制在约 250 行以内。
- 每个分析卡片独立一个组件文件。
- 分析计算逻辑和展示组件分离。
- 页面只负责组合模块，不直接写复杂统计公式。
- 新增数据必须经过校验。
- 新增功能至少补充关键逻辑测试。

## GitHub 协作方式

如果只是自己维护项目，可以直接提交到主分支：

```bash
git status
git add .
git commit -m "Update picker experience"
git push origin main
```

如果希望保留 review 流程，可以使用分支和 PR：

```bash
git checkout -b feature/picker-upgrade
git add .
git commit -m "Upgrade picker experience"
git push -u origin feature/picker-upgrade
gh pr create --base main --head feature/picker-upgrade --title "Upgrade picker experience" --body "完善分析驱动选号功能。"
```

PR 是 Pull Request，意思是“请求把某个分支的改动合并到目标分支”。多人协作、正式发布、需要代码审查时更适合用 PR；个人项目快速迭代时，直接提交并推送也可以。

Codex 里的 GitHub 插件更适合查看仓库、issue、PR、提交和 CI 状态，或者通过 GitHub API 做少量文件操作。本地项目开发、批量改文件、运行测试和构建，通常还是使用本地 `git`、`gh` 和命令行更稳。
