# 大乐透分析网页项目规范

## 项目定位

本项目是一个本地单页应用，用于查询、分析和娱乐化选号。所有趋势、评分、选号理由都必须标注“仅供娱乐，不构成购彩建议”。应用不承诺预测准确性。

## 数据规范

- `dlt_history_FULL.md` 只作为原始归档、导入来源和导出格式，不作为运行时主数据源。
- `data/dlt-draws.json` 是唯一可信主数据源，前区和后区都保存为数字数组。
- `data/dlt-meta.json` 保存数据版本、总期数、最新期号、最新日期、来源和生成时间。
- 展示层负责把数字格式化为 `01`、`02`；数据层不得保存带前导零的字符串号码。
- 任何导入、同步、手动新增都必须经过校验：期号唯一、日期合法、前区 5 个不重复且在 `1-35`，后区 2 个不重复且在 `1-12`。

## 工程规范

- 单个业务文件控制在约 250 行以内；超过时拆分 hooks、utils、types、子组件或配置。
- 每个分析卡片独立一个组件文件，计算逻辑独立放在 `src/features/analysis/calculators`。
- 页面组件只负责布局、状态组合和路由式切换，不写具体统计公式。
- 新增功能优先复用 `src/domain` 的规则工具和 `src/data` 的解析校验工具。
- 文件命名使用语义化英文，组件使用 PascalCase，工具和计算器使用 camelCase。

## 目录职责

- `src/data`：数据加载、解析、导入导出、校验。
- `src/domain`：大乐透规则、中奖判定、号码格式化、统计基础工具。
- `src/features/query`：历史查询、号码检索、中奖检查。
- `src/features/analysis`：分析页面、卡片注册、分析卡片和计算器。
- `src/features/picker`：娱乐选号器和策略解释。
- `src/features/manage`：单期新增、批量导入、导出和数据健康报告。
- `src/components`：通用 UI 组件。
- `src/charts`：ECharts 封装组件。
- `scripts`：数据导入、导出、同步、校验脚本。

## 分析卡片接口

新增卡片必须遵循统一输入输出：

- 输入：已按区间筛选的开奖数据、当前区间配置、全部开奖数据。
- 输出：统计结果、图表数据、摘要文案和娱乐提示。
- 卡片必须能在 `全部 / 近200 / 近100 / 近50 / 近30 / 近10 / 自定义` 区间下工作。
- 卡片组件不得直接读取 JSON 文件，数据由分析页面传入。

## 测试要求

- 数据解析必须覆盖当前 Markdown，可解析出 2869 条记录，最新期号为 `26051`。
- 中奖判定必须覆盖所有奖级和未中奖。
- 热冷、遗漏、和值、奇偶、大小、连号等统计必须能用固定样本复算。
- 构建前至少运行 `npm run data:validate`、`npm test` 和 `npm run build`。
